## Задание 2

**C++**
```
int main() {
   int a=1, b=2;
   int c=a++b;
   return 0;  
}
```

Последовательность токенов:

| int | c | = | a | ++ | b | ; |

В C++ запись a++b распознаётся как a | ++ | b. Поскольку ++ — унарный оператор, он применяется к a, а следом идёт b, причём между ними отсутствует какой-либо оператор. Из-за этого выражение оказывается синтаксически некорректным.

**Python**
```
a=1
b=2
c=a++b
```

Последовательность токенов:


| c | = | a | + | + | b |

В Python ++ не существует как единый оператор. Это два отдельных оператора +: первый — бинарный, второй — унарный. Соответственно, выражение разбирается так:

c = a + (+b)

При a = 1, b = 2 имеем c = 3. Значит, программа на Python синтаксически верна и выполняется без ошибки.

## Задание 3

*Рассмотрим следующую программу на языке С++.*
```
int main() {
   int a=1, b=2;
   int c=a+++b;
   return 0; 
}
```
Токенизация строки:

| int | c | = | a | ++ | + | b | ;|

Токенизатор отдаёт предпочтение самому длинному подходящему токену. В результате первые два плюса объединяются в оператор ++, а третий распознаётся как оператор +.

1.a++ берёт текущее значение a, то есть 1, а затем увеличивает a до 2.

2.Это старое значение 1 складывается с b, равным 2.

3.В итоге получаем c = 3.

Пробелы способны повлиять на разбиение на токены. Например:

int c = a + ++b;

Токены здесь:

| a | + | ++ | b |

В этом случае первым увеличивается b — до 3, затем выполняется a + 3, что даёт c = 4.
Таким образом, расстановка пробелов может повлиять на токенизацию и, как следствие, на смысл программы.

## Задание 5

Программа:

print(*map(sum, zip(
    *[map(int, input().split()) for i in (1, 2, 3)]
)))

- i — переменная цикла
- print — функция вывода
- map — функция отображения элементов
- sum — функция суммирования
- zip — функция объединения последовательностей по позициям
- int — функция преобразования в целое число
- input — функция чтения строки
- split — метод строки, разбивающий ее

- *Ключевые слова*
  
   - *for, in*
  
- *Идентификаторы*
  
  - *print, map, sum, zip, int, input, split, i*
  
- *Литералы*

  - *1, 2, 3*
  
- *Оператор*
    
    - (*)

### Вызываемые функции и параметры

- *print* - Выводит переданную последовательность через запятую или при распаковке — последовательность с заданными разделителем и завершающим символом (аргументом служит последовательность, полученная после распаковки map).

- *map* - Применяет функцию (sum), переданную первым аргументом, к каждому элементу последовательности, которая подана вторым аргументом.

- *zip* - Попарно объединяет по позициям три последовательности, полученные через запятую либо в результате распаковки.

- *map*  - Преобразует элементы подаваемой последовательности (в данном случае, строки) в целые числа.

- *input()* - Считывает одну строку.

- *input().split()* - Выполняет разбиение введённой строки по пробельным символам, которые используются по умолчанию.

- *sum* - Хотя явного вызова нет, при выполнении она суммирует элементы одной из последовательностей, которые передаются в map.

### Что делает программа

Программа три раза читает строку чисел:

for i in (1, 2, 3)

Переменная i нужна только для выполнения цикла три раза.

Для каждой строки:

1. input() читает строку
2. split() разбивает её на отдельные значения по пробелам
3. map(int, ...) превращает значения в числа

В результате имеем три последовательности чисел. zip группирует их по столбцам, после чего map(sum, ...) вычисляет сумму элементов каждого столбца. Далее print(*...) распаковывает найденные суммы и печатает их, разделяя пробелами.

## Задание 6

В C++ используются два вида комментариев:

```cpp
// однострочный комментарий
```

```cpp
/* многострочный комментарий */
```

Комментарии не участвуют в дальнейшем разборе программы.

## Синтаксически верные

- *1. Строковый литерал*

```
cout<<"Hello /* Это комментарий */ world";
```

поскольку данная последовательность находится внутри строкового литерала, она является обычным содержимым строки, а не комментарием.

- *2. Однострочный комментарий*

```
// Я комментирую программы /* комментарий */
```

Все, что находится после //, игнорируется. Наличие внутри этой части последовательности /* ... */ ничего не изменяет.

### Синтаксически не верные

```
// /*
 Это комментарий
*/
```
Всё, что идёт после // до конца первой строки, относится к комментарию. Следовательно, /* не начинает многострочный комментарий. Последующие строки уже не являются частью //-комментария, а одиночный */ не имеет соответствующего открывающего /*.

- *2. Вложенный многострочный комментарий*

```
/* Я комментирую программы /* комментарий */ */
```
В C++ многострочные комментарии не допускают вложенности. Завершает комментарий первый встреченный */, тогда как последний */ оказывается лишним.

- *3. Многострочный комментарий с `//`*

```
/* Я комментирую свои программы
// Это комментарий до конца строки */
*/
```
Если // встречается внутри уже открытого /* ... */, отдельный однострочный комментарий не возникает: всё вплоть до первого */ по-прежнему принадлежит многострочному комментарию. Затем остаётся второй */, не имеющий парного /*.
